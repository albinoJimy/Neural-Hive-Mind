# Spec Summary (Lite)

Fechar o loop de aprendizagem (D6/LEARN) do NHM como Fundação transversal (plano-Z do modelo harmonizado, ADR-0011), não como patch acoplado à capacidade EXECUTE. Hoje `actual_duration_ms` já viaja em `execution.results` mas o `execution_result_consumer` descarta-o (só envia signal Temporal), pelo que `execution_tickets` fica sem o campo (3/1247) e o `duration_predictor` treina cego; há ainda um bug de contrato de tipo (timestamps gravados em epoch millis vs filtro `$gte datetime` que nunca casa). A entrega cria um contrato canónico `ExecutionFeedback` (capability-agnostic) + um `FeedbackSink` transversal idempotente, transforma o consumer num adapter EXECUTE fino, alinha o predictor (millis + exclusão de simulados), e deixa os ganchos `capability`/`journey_id` prontos para o Roteamento e as Capacidades (GENERATE/MIGRATE) encaixarem depois — respeitando **Fundação → Roteamento → Capacidades. Nunca o inverso**. Cirúrgico (~3 ficheiros + 1 módulo novo), encaixa em `feat/convergencia-dbs`.
