# Spec Summary (Lite)

Introduzir **Journey** como conceito de primeira classe (passo 2 do ADR-0011: Fundação → **Roteamento** → Capacidades) com um classificador de jornada **inteligente e híbrido** no STE. Hoje o roteamento é difuso (workflow_classifier por keywords no STE + decision_consumer re-deriva no orchestrator) e não há `journey_id` nem segmentação do loop LEARN. A spec entrega: enum `Journey` (J1_PLAN_ONLY, J2_ORCHESTRATE, J3_BUILD, J4_MIGRATE, UNKNOWN) em `neural_hive_domain`; um `JourneyClassifier` em 2 tiers (Tier 1 sinais estruturados determinísticos — source de ingestão→J4, execution_mode→J1, workflow_type→J2/J3; Tier 2 LLM via `neural_hive_llm` para casos ambíguos) com `confidence`/`reasoning`/`UNKNOWN` no padrão anti-verde-falso do NLU; propagação do `journey_id` no cognitive_plan → decision_consumer (roteia POR journey) → ExecutionFeedback (gancho já pronto da Fundação); marcador `context.source="doc-ingestion"` para J4; e métricas com label `journey`. Decisão tomada cedo (STE), propagada início→fim. Aproveita o gancho `journey_id` deixado pela Fundação.
